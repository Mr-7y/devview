# Ai-View — 评估标准

总分 10 分，加权求和。通过线 7.5。任一"硬性项"不满足，总分封顶 6.0。

| 维度 | 权重 | 评什么 |
|---|---|---|
| 设计质量 Design Quality | 0.35 | 层级、留白、对齐、对比度、主题完整度、长时间阅读的舒适度 |
| 原创性 Originality | 0.30 | 是否脱离 VS Code / JetBrains 的既视感；顶栏 git 带是否有独立记忆点 |
| 工艺 Craft | 0.25 | 像素级对齐、字体回退、状态细节（hover/focus/dirty/toast）、代码高亮质量 |
| 功能性 Functionality | 0.10 | 需求是否真实可用，而不是截图占位 |

## 硬性项（缺一即封顶 6.0）

- [ ] 暗色与亮色两套主题都完整，切换后无残留色
- [ ] 顶部可见 git 工作流：分支、远程、ahead/behind、提交框、提交/推送
- [ ] 字体可配置：界面字体、代码字体、字号、行高，且实时生效
- [ ] 代码区可编辑并产生脏标记，保存有反馈
- [ ] 图片预览存在
- [ ] 安装包/版本/作者 Mr.7y 可见
- [ ] 无外部资源依赖

## 分档锚点

**9–10**：有资格作为产品发布的主视觉；结构与配色均有辨识度；细节经得起放大看；两套主题像两个完整产品而不是反色。
**8–8.9**：完成度高，有 1–2 处让人记住的设计决策，细节偶有瑕疵。
**7–7.9**：专业水准，但结构或配色仍能看到参考对象的影子。
**6–6.9**：功能齐全，视觉平庸或存在明显不协调。
**< 6**：模板感强、信息拥挤、主题不完整。

## 评估问题

1. 第一眼是否像一个"产品"，而不是一个练习稿？
2. 关掉颜色只看灰度，层级是否依然成立？
3. 顶部 git 带是否承担了真实工作流，而不是装饰？
4. 代码区是否愿意让人连续读 30 分钟？
5. 亮色主题是否经过重新设计（纸感、墨色、阴影），而不是简单反色？
6. 放大到 200% 看，对齐与字距是否仍然干净？
7. 有没有一个"别处没见过"的细节？
