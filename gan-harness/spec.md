# Ai-View — 设计规格

## 一句话

把代码放回阅读的位置：一款可编辑、可换肤、以 git 工作流为顶栏的桌面代码浏览器。

## 产品信息

- 名称：Ai-View
- 作者：Mr.7y
- 形态：桌面应用，以安装包分发（Windows / macOS / Linux）
- 定位：主流代码浏览器，比 IDE 轻，比阅读器强
- 参考对象：VS Code、JetBrains、Zed、Sublime Merge、GitHub Desktop、Linear

## 用户要求（逐条可验收）

1. **可编辑的代码浏览器**：不是只读查看器，支持输入、脏标记、保存反馈。
2. **可配置字体**：界面字体与代码字体分别可选，字号、行高可调，改变即时生效。
3. **双主题**：一个夜间（默认）、一个白天，可随时切换，两套都要完整。
4. **代码间距要大**：行高明显高于常见编辑器，强调"阅读感"，长文件不压抑。
5. **git 工作流放上面**：分支、远程、ahead/behind、提交框、提交/推送/拉取全部在顶部一条工作流带里完成。
6. **有远程仓库**：侧栏展示 origin / upstream，含地址、同步状态与拉取推送入口。
7. **图片**：支持图片预览（尺寸、体积、缩放）。
8. **安装包形式**：界面内可见版本、安装包体积、更新通道，不做浏览器标签页式的产品感。
9. **名字 Ai-View，作者 Mr.7y**：品牌与署名必须出现在界面中。

## 设计命题

主流代码浏览器长期被两种范式统治：VS Code 的蓝色工作台，和 JetBrains 的高密度灰。二者都为"编辑效率"优化，代价是视觉噪音与压迫感。Ai-View 的机会在"阅读"这一侧：

- **温度**：用暖中性色（墨、纸、黄铜）替代冷灰蓝，降低长时间阅读的疲劳。
- **呼吸**：更大的行高、更宽的内边距、更少的边框，让代码成为页面的主体。
- **秩序**：git 不是藏在侧边的一个面板，而是横贯顶部的"工作流带"，提交这件事始终可见。
- **克制**：不使用高饱和强调色；颜色只用来标记状态（变更、新增、冲突）。

## 视觉基调

| 维度 | 决定 |
|---|---|
| 夜间主题 | 墨黑底（#0D0F12），黄铜强调（#D3A95F），玉色表示新增（#5FBF94） |
| 白天主题 | 纸白底（#F6F4EF），深棕强调（#9A6A25），墨色文字（#1C1E22） |
| 字体 | 界面用系统无衬线，代码用等宽；字号与行高均可调 |
| 圆角 | 控件 8px，卡片 12px，胶囊 999px |
| 描边 | 1px 半透明细线，不用重阴影 |
| 间距 | 8px 栅格；面板内边距 16–24px；代码区左右 32px |
| 动效 | 120–220ms，ease-out；只用于状态变化，不做装饰性动画 |

## 必须实现的交互

- 主题切换（夜航 / 日纸），全部界面同步
- 字体、字号、行高修改后实时应用
- 代码区真实可输入，产生脏标记；Ctrl/Cmd+S 保存并提示
- 标签切换（代码 / 图片 / README）
- 提交框输入后启用提交按钮，提交后更新计数并提示
- 命令面板（Cmd/Ctrl+K）可开可关
- 图片预览的缩放切换

## 红线

- 不使用 CDN、外部字体或远程图片；断网可打开
- 不做 VS Code 换色皮；顶部 git 带与阅读型代码区必须是可辨识的原创结构
- 不以牺牲可读性换装饰；不用高饱和渐变堆砌"科技感"
